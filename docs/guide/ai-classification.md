# The AI classification and what it uses

Part of the project guide (moved out of `CLAUDE.md`; text unchanged). Read this before changing this area.

- **Classify a saved picture** (the page of a picture, `play-picture-form`): the button "Let the AI set categories, name and description" calls `JigsawService.classify(id, true, language)` with the language chosen in the form (`NewPicture.classify`), puts what it got in the form (so Save sends the same) and shows why when it fails. It is off while a new picture or cut waits to be saved. Choosing another language alone does not call the AI. A new picture has **Save and analyse with AI** instead, and many at once asks the AI for each.
- **Where the categories are shown:** as badges (`app-category-tags`) on the cards, on the page before the puzzle, in My pictures and in many at once.
- **The kind does not matter to the classification:** a picture entry (`kind: 'picture'`) is classified like a ready jigsaw (the stored picture is what the AI looks at, and the motive difficulty is a property of the picture), and `apply` keeps the kind, with no grid, store or difficulty.
- **What the AI uses is kept for the user who pays** (token use, to be paid for later): each call of the classification (`POST /jigsaw/:id/classify`) that the AI answered keeps one document in the subcollection `jigsaw-users/<uid>/token-usage/<id>` (`JIGSAW_TOKEN_USAGE`, `TokenUsageSpec`, `models/shared/token-usage.ts`; `functions/src/jigsaw/token-usage.ts`, `TokenUsageStore`; the user is the one in `X-Jigsaw-User`, else the owner): `provider`, `model` (asked for) and `responseModel`, `requestId` (OpenAI's id of the call), `inputTokens`, `outputTokens`, `totalTokens`, `cachedInputTokens`, `reasoningTokens`, `imageDetail`, `kind` (`classify`), `jigsawId`, `status` (`ok`, or `failed` when the answer could not be used: the tokens are spent all the same, `AiFailed.usage`; the call to OpenAI itself is `common/openai-chat.ts`, which the translation of the tiles uses too), `applied` (put on the jigsaw), `createdAt` (ms) and `date` (ISO text), and `billed` (false until a payment takes it in). `TokenUsages.fromOpenAi` reads OpenAI's `usage`, `record` makes the document, `totals` adds up (also what is not yet billed). A call that could not be asked (503) or was refused (403) keeps nothing; keeping never fails the classification. The user reads their own with `GET /jigsaw/api/jigsaw-users/:id/token-usage` (`{items, totals}`, 403 to anybody else). The classification the page gets does not carry the use. No price is kept (prices change: work it out from the tokens and the model when billing).
- **AI classification of one jigsaw** (OpenAI; `POST /jigsaw/api/jigsaw/:id/classify`, `?apply=true` to save): the AI looks at the stored picture and says its **categories, a name and a description**, the texts written in the language of the jigsaw. Only the owner may (403 otherwise; 404 no jigsaw, 409 no picture, 503 when the settings are not there, 502 when OpenAI fails). Without `apply` nothing is saved; with it the categories (when it said some), the name and the description (when it said one) are put on the jigsaw and nothing else of it changes. **The motive difficulty** is a property of a jigsaw, like its difficulty, and not a category: `JigsawSpec.motive` is one of `easy`, `mediumeasy`, `normal`, `hard`, `expert` (`models/shared/motive.ts`, `JigsawMotives`; how hard the picture itself is to put together, from how easy it is to tell its parts apart: **a picture with few distinct details (a sky, a calm sea, one colour, a repeating pattern) is harder than one with many different details**, because the pieces look alike; **the AI does not choose the level: it gives three ratings (`detail` and `colour`, each 1-5, and `landmark`, true or false) and the level is worked out from them by `JigsawMotives.fromRatings`: detail is how many different shapes, objects and textures, colour is contrast and colour (how strongly the parts differ in brightness and colour); the two add up: 9-10 easy, 7-8 medium easy, 5-6 normal, 4 hard, and 2-3 (almost no detail and almost no contrast or colour) expert, except that something that clearly stands out (a mark, a line, an object: `landmark`) makes that hard, for example a white check mark on a blue wall; the AI is told to give the lower number when in doubt; the five levels and their words are unchanged**; not from the number of pieces; none until somebody says it). It is stored, read (`fromStored` also takes a `motive/hard` that an older version kept among the categories and makes it the property) and checked by `JigsawSettings`; it is not one of the things every round shares, so it can change at any time. The answer has the three ratings (the schema has no `motive` field; `Classifications.read` works the level out, and still takes a `motive` said outright when there are no ratings) and the route puts the level on the jigsaw with `apply`. It is found like the difficulty: `motives` in the search, the filter (`JigsawFilter.motives`) and the counts (`JigsawIndex.motive`, `motive` is a summary field); a jigsaw with none is never found by it. The form of a picture has a row of small buttons for it under Advanced (`jigsawNew.motive`), and the cards, the page before the puzzle and My pictures show it beside the difficulty with the icon `bi-bullseye`. The texts are `jigsawLevels.motive.*`. The model class is `Classifications` (`models/shared/classification.ts`): the strict JSON schema with the category keys as the only values, the prompt (the categories, the limits, the language), and `read`/`tidyCategories` which check what comes back (only categories that exist, at most three, a sub-category instead of its category, "other" only when alone; texts tidied and cut to `JIGSAW_MAX_NAME` and `JIGSAW_MAX_DESCRIPTION`). `Classifier` is the port (`functions/src/jigsaw/classifier.ts`): `openAiClassifier` calls the Chat Completions API with `fetch` (the picture as a data address at `OPENAI_IMAGE_DETAIL`), `configuredClassifier` reads the settings when asked, and tests use a fake: **no test calls OpenAI**. **The settings are in the top-level `/.env`** (git-ignored; the template is `.env.example`): `OPENAI_API_KEY` (a *project* key; never an admin key), `OPENAI_MODEL` (required, no default), `OPENAI_IMAGE_DETAIL` (low by default), `OPENAI_ORG_ID`, `OPENAI_PROJECT_ID`. `scripts/sync-env.mjs` (`npm run sync:env`, run before every functions build; `--check`, `--soft`) copies them: the settings that are not secret to `functions/.env` (the emulator reads it and a deploy takes it), **the key only to `functions/.secret.local`** (the emulator only, never deployed, a deployed function gets its key from the Firebase secret `JIGSAW_OPENAI_API_KEY`, declared on `jigsawApi` (`defineSecret`; the name is the jigsaw's own because the project is shared). **`npm run deploy` and `deploy:functions` run `sync:env` and then `scripts/deploy-secrets.mjs` first**, which puts the key of `/.env` in that secret (on the standard input of `firebase functions:secrets:set`, never on a command line or in a log) and stops when the key is missing; `.secret.local` has the key under both names, since the emulator reads a declared secret by its name; `openAiSettings` takes either). Never put a key in the repo, a file that is deployed, or a chat. `npm run classify:dummies` shows what the AI would say for 3 dummy jigsaws (`--count N`, `--all`), and `-- --apply` saves it; each picture is sent to OpenAI.
