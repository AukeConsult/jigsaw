# The look and the texts

Part of the project guide (moved out of `CLAUDE.md`; text unchanged). Read this before changing this area.

- **Font sizes: ONE scale of FIVE sizes in `styles.scss`** (tokens `--app-fs-title`, `-heading`, `-text`, `-small`, `-tiny`, each made with the `fluid(min, max)` function: the first size (rem) on a phone 375 px wide or less, the second on a screen 1400 px wide or more, a straight line between). Nothing else sets a text size: Bootstrap's `h1` and `.h1`, `h2`-`h6` and `.h2`-`.h6`, `.lead`, `.small`, `.btn`, `.form-label`, `.form-check-label`, `.form-text`, the fields, `.badge`, `.invalid-feedback` and the navbar name are set to the tokens there, and templates use `.page-title` (h1), `.section-title` (h2), `.subsection-title`, `.tiny` (dates, details), `.icon-md` instead of picking a Bootstrap heading size (`h3`, `h4`, `fs-3` ...). No component sets a `font-size` of its own (the logo is on the scale too); a size that is not one of the five is not added: use the nearest. What each is for and how big it is (phone 375 / tablet 768 / desktop 1400 px, text 16 px at least in a field so a phone does not zoom in): **title** (the page title) 22.4 / 26.1 / 32; **heading** (h2 and under, the line under a title, the name in the header, an icon beside a heading) 18 / 20.3 / 24; **text** (the text, what is typed in a field, the main button) 16 / 16.8 / 18; **small** (the label of a field and of a switch, the help and the error under a field, notes, the text of every other button) 13 / 13.8 / 15 (the label is about 80 % of the text of the fields); **tiny** (dates, details, badges, the subtitle of the logo) 9 / 9.1 / 9.3.
- **Buttons have three sizes, also a scale in `styles.scss`** (`--app-btn-*`: the text of a button is `--app-fs-small`, the main button's `--app-fs-text`; the room round the text and the gap to the icon are in `em`, so they follow the text size and a button keeps its shape; more room on a touch screen; the icon in a button is 1.15em and spaced by the gap, so a template needs no `me-1` on it): `.btn` the usual, `.btn-sm` the small one in rows and lists (also `.btn-group-sm > .btn`; it differs from the usual one by less room, not by its text), `.btn-main` (same as `.btn-lg`) the big one for the main action of a page. Never size a button in a template or a component.
- **Texts are translated (Transloco), jigsaw module only, in en, nb, sv, da, fi, de, fr, es, nl** (same way as the Seven Friends project): files `frontend/public/i18n/<lang>/<scope>.json`, scopes `jigsawHome`, `jigsawList`, `jigsawUser`, `jigsawNew`, `jigsawPage`, `jigsawPlay`, `jigsawShell`, `jigsawBoard`, `jigsawCropper`, `jigsawExample`, `jigsawLevels`, `guide`. A template declares `provideTranslocoScope('<scope>')` and `*transloco="let t"` and ALWAYS writes the English next to the key (`{{ t('jigsawHome.title') || 'Karins jigsaw' }}`); TypeScript uses `tr('scope.key', 'English')` from `core/i18n.ts`. New text: add the key to all four languages in the same change, then run `npm run check:i18n`. The language is chosen in the menu and kept in `localStorage` (`jigsaw.language`); the browser's language is NOT used (English until chosen). The guide has one file per language (`frontend/public/i18n/<lang>/jigsaw-guide.md`). Not translated: messages that come from the API or from the generated shared models. A long text must wrap inside the view, never flow outside it (check at 320 px in sv).
- **A long form is grouped in sections** (`.form-section` in `styles.scss`: an `h2` with a small icon and words over a thin rule, `first` for the one at the top; used on the pages for a new jigsaw, the edit panel of a jigsaw and the forms of a user). One form: labels are plain `form-label` (not `small`), a field has `mb-3` and a row of fields `g-3 mb-3`; the sidebar of a round is the only place with small labels. Edit, Delete and the actions that change the picture are `.link-action` in a `.toolbar`, and so are the actions of a row of rounds (Continue, Look, Delete, and the question before a delete: `.link-action`, `.danger` for the delete); Cancel and Save of a form are `.btn-outline-secondary` and `.btn-primary`. New headings are new keys in all nine languages.
- **The toolbar is one standard in `styles.scss`** (a row of plain words, no boxes, no padding at the sides, so every text starts where it looks to start and lines up with what is above and below it): `.toolbar` the row (one gap size), `.segmented` a switch of choices in it (radio `btn-check` + `btn` labels; the picked one is blue, bold, underlined), `.link-action` a text that does something (icon and words; `.danger` for a delete), `.toolbar-end` pushes a part to the right end, `.toolbar-note` the tiny line under it ("3 jigsaws"), and `.link-inline` a word in a sentence that does something. Use them for every such row, now and on future pages; no `btn-link`, `px-0` or `p-0` tricks in a template.
- **Hiding in templates:** Bootstrap's `d-flex`, `d-none` and friends use `!important`, so the `hidden` attribute (or `[hidden]`) does NOT hide an element that has one of them: use `@if` (the buttons that start or delete a round were once "hidden" this way and still showed).
- **Words:** in the pages and the guide one game of a jigsaw is a **round** ("New round", "Delete round", "Your rounds"); in the code and the API it is a **play** (`PlaySpec`, `/plays`, `plays.service.ts`). The older notes here and in `api-and-code.md` that say "game" mean a round.
- **Account, not user:** in every text the person reads (the nine languages, the English fallbacks in the templates, the messages of the API and of the model) the one who plays is an **account** ("Choose another account", "Delete this account", "Show other accounts"); the **user name** stays the name of the handle ("User name"), and **login** is a Firebase sign-in. In the code, the API, the stored data and the guide files the class is still `JigsawUser` (`JigsawUsers`, `jigsaw-users`, `X-Jigsaw-User`): only the words people read changed. A person who plays is called a player, and "By player" in the list of rounds stays.
- **Plain words for the sign-in:** the Firebase side is a **sign-in** (Google, an emailed link or a password; "Sign in", "Sign out"), the player is an **account**, and an account that only some sign-ins may use is **locked** (one lock icon everywhere: the list of accounts and the rounds of a locked account). Short sentences, one idea each; a message says what is wrong and what to do next. An account with one sign-in only is told to add a second, so it cannot be lost (`userLogins.lockoutHint`). The code keeps the old words (`logon`, `protected`); only the texts changed.
- **Hard parts are kept short:** the link code is told as three numbered steps (`jigsawUser.codeHowTo`, `codeStep1` to `codeStep3`), the less used choices of the signed-in box (a link code, another sign-in) are behind **More** (`app-my-logon-users`), and no text shows a message meant for the developer (the errors of Firebase are turned into "try another way").
