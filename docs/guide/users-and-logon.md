# Users, signing in with Firebase, and language

Part of the project guide (moved out of `CLAUDE.md`; text unchanged). Read this before changing this area.

- **A new person only says their name** (`/jigsaw/user` starts in mode `start`: the title is "What is your name?", one field and the button "Start playing"; `JigsawUserService.createFromName` makes the user with a user name worked out from the name, `JigsawUsers.usernameFrom(name, digits)`: the plain name first, four digits added only when the server answers 409 (taken), never for another error (a taken user name makes nothing: `createFromName` says which user name, `lookup` reads that user and the page asks). When somebody already has it (what was typed is the whole name, the whole user name or a whole word of either, in any case and ignoring accents: `JigsawUsers.matches`, two letters at least, so "leif" finds "Leif Auke" and `leif-auke-5`; or it is the user name the typed name would make) the page first asks "Is that you?" (`JigsawUser.sameUsers`, a list to choose from when several have the name): "Yes, that is me" plays as that user, "No, make a new user" makes one with digits). The list of the users is behind "I have played before" (so nobody presses a name that is not theirs) and the whole form (user name, language, e-mail) behind "Choose my own user name".
- **Signing in with Firebase** (`functions/src/logons/` and `frontend/src/app/logons/`: **everything about it is in these two folders**, beside the users of the jigsaw above, which it does not change: they still use `X-Jigsaw-User`, `userGuard` and `/jigsaw/user`, and nothing else uses the new login yet). The project is shared with Seven Friends, so a Firebase login is one login for both apps and the account is the same document, `user-account/<Firebase UID>`. `POST /jigsaw/api/session` (the page sends `Authorization: Bearer <ID token>` after it has signed in) checks the token (`require-auth.ts`: `verifyIdToken` and the look-up of a deleted login, as Seven Friends does) and makes or updates that document (`account-store.ts`, one transaction): `uid`, `email`, `emailLower`, `emailVerified`, `verifiedPhone`, `phoneKey`, `phone`, `displayName` (a name that is there stays; the login's name is only the start), `photoURL`, `provider`, the stamp `accountId` (made once, never changed), `lastLoginAt`, `loginCount` and `createdAt`. What Seven Friends keeps in the same document (profile, circles, medals, setup) is left as it is, and no circle is made here: Seven Friends makes it when the person opens it. The rules are on the model `LogonAccounts` (`models/shared/logon.ts`: `stored`, `publicOf`; tested in `functions/test/logons.test.ts` with a fake verifier, no call to Firebase). **Frontend:** `logons/firebase.ts` (the Auth emulator is on port 9109), `auth.service.ts` (Google, email and password, the emailed link; every way ends in `finishLogin`, which calls the session route and signs out again when that fails), `auth-errors.ts`, `auth.guard.ts` (`authGuard` with `?next=`, `guestGuard`), the pages at the **top level**: `/login`, `/login/email` (ask for the link), `/login/link` (the page the link opens), `/account` (who is signed in, Sign out; behind `authGuard`), all inside `JigsawShell` (`logons.routes.ts`), and a menu entry that says Sign in, or Account when somebody is signed in. Texts: the scope `logons` in the nine languages (the Seven Friends translations reused). Not built: phone (SMS), the page that finishes a verification email (the project has one template for both apps, so such a link opens Seven Friends' page first), native Google sign-in in the Android app, and any use of the login by the rest of the API. Moving the old users to these logins is a later step.
- **Language:** the languages are one list, `JIGSAW_LANGUAGES` (`models/shared/language.ts`: en, nb, sv, da, fi, de, fr, es, nl; `JigsawLanguages.is/of/nameOf`; the app's `LANGUAGES` is that list). **A user has a `language`** (English until chosen; set in the form on `/jigsaw/user`, made or changed with `language` on `POST`/`PUT /jigsaw/api/jigsaw-users`; `JigsawUserService` shows the app in the language of the user when the user is chosen or read, and a language chosen in the menu is kept as the user's, `changeLanguage`). **A jigsaw has an optional `language`** (what its name and description are written in; English when it says nothing: `JigsawLanguages.of`): the form of a new jigsaw starts it as the language the app is shown in (the user's), and the form of an edit and the edit panel of a played jigsaw change it (it is not one of the things every round shares). It is kept for finding (`language` in `JigsawIndex`) and can be searched (`languages`, a list, in the filter).
